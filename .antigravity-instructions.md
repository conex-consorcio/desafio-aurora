# Instruções Específicas do Projeto - Desafio Conex

**Objetivo:**
Atuar como assistente técnico na análise e implementação dos Casos 1 (Lance Duplicado) e 2 (Sincronização de Cotas) do desafio Conex. A solução deve focar em resiliência em ambientes distribuídos e respeitar estritamente a arquitetura existente no repositório.

## Regras da Casa (Obrigatórias)

1. **Camada Anticorrupção (ADR-0001):** Todo dado da API da Aurora é "cru" (`aurora-*.types.ts`), deve ser validado (`aurora-*.validation.ts`) e nunca atravessa para o domínio. Use `view-models`. O módulo `src/modules/parceiros` é a referência oficial.
2. **Sem Fabricação de Dados (ADR-0002):** É ESTRITAMENTE PROIBIDO usar `?? 0`, `|| 0`, `as any`, ou `!` sobre dados da Aurora. Campo ausente deve virar `undefined`. Em caso de formato inesperado, descarte o campo e registre um warning sem dados sensíveis (PII).
3. **Race Hunter:** Evite janelas _Check-then-act_. Use locks granulares no Redis para o Caso 1. Para o Caso 2, limite a concorrência assíncrona com timeout estrito e trate o Graceful Shutdown para não perder requisições em andamento caso ocorra um `SIGTERM`.
4. **Testes:** Foco em comportamento e contrato, não em cobertura cega. Testes não devem asserir o próprio mock.

## Restrições de Segurança do CLI (Automação Controlada)

- **Permitido sem confirmação:** Leitura de arquivos, varredura de diretórios e execução de scripts de teste local (`npm run test`).
- **Exige confirmação manual (BLOQUEADO POR DEFAULT):** Mutações de código, comandos `git` (`commit`, `push`, `merge`, `reset`, `rebase`) e comandos de infraestrutura (`docker compose up/down/restart`).
- Sempre que precisar executar uma ação bloqueada, pare o processo e exiba: _"Aguardando confirmação do usuário para executar: [COMANDO]"_.
- **Não altere** nenhum arquivo dentro da pasta `stub/`.
